# 四层 Transformer 动作意图模型

当前小模型已经替换为七分类动作意图模型：`GRASP`、`PLACE`、`MOVE`、`STOP`、`RUN_TASK`、`CLARIFY`、`UNSUPPORTED`。只保留一个动作输出头，没有颜色或方向分类。

模型结构为四层 Encoder，`d_model=192`、4 个注意力头、前馈维度 768，共 1,836,487 个参数。默认使用 CPU。训练、数据、权重、评估和曲线全部保存在本目录。

## 真实训练记录

当前 v2 使用随机种子 `20261022`，从 v1 继续训练；已有 token 的嵌入按名称迁移，新 token 初始化后共同训练，四层 Encoder 和七类输出保持不变。学习率 `0.0001`，本机 CPU 训练 17 轮，验证集 loss 最佳为第 9 轮，约 88 秒。置信度阈值 **0.6** 由 279 条验证数据按原有策略选择：在通过样本分类准确率达到 98% 的候选中优先覆盖率，并非针对某条失败指令手工降低。

在同一组 350 条受控开发回归句式上，v1 → v2 的原始分类准确率为 **83.14% → 92.29%**，macro F1 为 **0.8273 → 0.9188**。训练当时使用置信度和未知字符比例两项门槛，存档通过率为 97.14%，通过样本的分类准确率为 93.53%；验证集上的 98% 要求不保证能在其他数据上达到。这些通过率属于取消未知字符比例门槛前的记录，不代表当前推理策略的通过率。原始 84 条句式的分类准确率为 **92.86% → 94.05%**。真实错误保留在 [test_metrics.json](experiments/intent_v2/test_metrics.json)，原模型同组结果见 [baseline_on_v2_test.json](experiments/intent_v2/baseline_on_v2_test.json)。

三个集合按基础句式划分，相同句式的礼貌词和开场变体不跨集合，标准化后文本也无跨集合重复。验证集参与选模和阈值选择；350 条数据用于开发回归比较，不参与反向传播，不能视作完全盲测或开放域准确率。用户原句的占位符形式“想一想，我要<TASK>”只在测试集出现。置信度是模型 softmax 分数，不是物理抓取成功概率。

第一次随机初始化训练的候选在旧句式上退步，未采用；数据、权重、曲线和错误保留在 `random_initialization/`。当前版本采用保留 v1 表达能力的继续训练方案，没有删除不利实验结果。

## 推理与训练命令

在项目根目录使用已安装 PyTorch 的环境。以下命令沿用原训练环境 `.venv_train`；按项目 README 新建 `.venv` 的使用者，将解释器路径替换为 `.venv/bin/python` 即可：

```bash
# 只测试模型意图；实际网页会先把数据库名称替换为占位符。
.venv_train/bin/python -B -m llm.model '帮我把<OBJ>拿起来'

# 重现当前继续训练流程，会替换 intent_v2.pt 和 v2 实验记录，保留 v1。
.venv_train/bin/python -B -m llm.train --epochs 25 --learning-rate 0.0001 --init-checkpoint llm/checkpoints/intent_v1.pt

# 使用独立测试集重新评估当前权重。
.venv_train/bin/python -B -m llm.evaluate
```

需要保留旧实验时，使用 `--checkpoint` 和 `--output` 指定新的权重及实验目录。数据生成命令 `.venv_train/bin/python -B -m llm.dataset` 会重新写入三个数据文件，只在明确需要重新生成时运行。修改数据后需要重新训练，重新评估并如实保留实验结果。

## 新增目标为什么不用训练

```text
用户：帮我抓取客户零件甲
数据库：客户零件甲 -> object_id=5
模型输入：帮我抓取<OBJ>
模型输出：GRASP
执行：查询物体5的坐标和技能
```

`<OBJ>`、`<TASK>` 从第一次训练起就是各占一个 ID 的特殊 token。物体名称、任务名称、坐标和步骤不进入模型词表。新增目标、别名和已有技能的组合任务只修改 SQLite，不更新模型文件。

独立放置点也由数据库管理。应用支持“把零件A放到放置区A”→“把<OBJ>放到<OBJ>”，由数据库区分物体和目的地角色，模型仍输出 PLACE。v2 数据包含对应双目标放置句式；新增地面或方块顶部放置点仍只更新数据库。放置必须先有持物且明确指定目的地。

## 口语表达与名称匹配

后端按数据库目标和现有动作词定位唯一命令，不枚举闲话或指定开场白。例如“我在大游戏，现在我口可乐，我想抓取1”，在名称 `1` 已登记时，完整替换结果为“我在大游戏,现在我口可乐,我想抓取<OBJ>”，但实际只将“抓取<OBJ>”交给模型。`normalized_instruction` 和 `model_input` 分别保存这两项，动作类别和置信度来自对 `model_input` 的真实模型预测。原句中没有标点时，也可按动作词和目标范围提取片段。只有任务名称而没有额外动作词时，用 `<TASK>` 调用。定位规则不直接映射动作类别，不替代 Transformer 推理。

整句词语白名单和未知字符比例门槛已移除；后端仍检查原句中的明确条件、否定、询问、预约时间、并列目标、多动作和相对位置，避免提取时丢弃关键要求。“抓取1，放下”即使没有连接词也属于多个命令；“开始抓取1”只计一个命令。“想一想，别动”统一提取动作分句“别动”后由模型预测 STOP，无需单独认识“想一想”。纯闲话没有目标或动作词时不调用模型执行。独立停止按钮继续不依赖模型。v2 的训练数据和权重均未因此修改。

名称匹配仍使用数据库登记的名称和别名，优先保留最长匹配，默认只允许一处目标；放置可包含一个物体和一个放置点。若只保存“收拾零件”，想用“整理零件”调用，应把后者加入该任务的别名；模型不会替数据库猜测任务身份。中文按连续字符串匹配，例如只登记“零件A”时，“大零件A”中的“零件A”也会被替换，后端不推断“大”是否属于另一个名称；需要区分时应登记完整名称。ASCII 字母数字名称保留边界检查，A 不匹配 AB。新建目标或别名不需要再次训练。

`MOVE` 仅识别移动意图，位置由已登记点位或任务中的绝对坐标提供。不识别相对方向，也不预测坐标数值。

未收录的字符正常编码为 `<UNK>`，不再根据未知字符比例拒绝输入。`unknown_ratio` 仅保留为诊断字段，不参与是否接受的判断；今后训练时的置信度阈值选择也采用相同策略。现有权重和阈值没有修改，无需重新训练。动作、置信度和长度限制仍由原模型代码处理，放宽检查不保证模型能理解任意表达。执行前还会检查技能、参数和当前持物状态。模型不可用时报告错误，不使用规则假装模型结果。
