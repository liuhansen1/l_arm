# Panda Studio 网页工作台

前端代码和资源集中在本目录，使用原生 HTML / CSS / JavaScript，无构建步骤，也无需 npm install。网页与真实仿真通过 `api.js` 的 HTTP 适配器通信。

## 一条命令启动网页与机械臂

在项目根目录运行：

```bash
.venv/bin/python -B launch/web.py
```

该命令启动现有 Panda 七轴机械臂和红、绿、蓝方块的真实 PyBullet 物理仿真、相机采集、SQLite 存储和网页 HTTP 服务，并自动打开 **http://127.0.0.1:8080**。不需要先运行另一个演示程序。

也可以在 `frontend/` 运行 `npm start`，效果相同。不要用原来的 `python3 -m http.server` 代替此启动器：静态文件服务无法驱动仿真或执行抓取。

```bash
.venv/bin/python -B launch/web.py --gui
.venv/bin/python -B launch/web.py --no-browser --port 8090
```

`--gui` 同时打开 PyBullet 原生窗口；默认在 DIRECT 模式下进行真实物理仿真，画面显示在浏览器。`--no-browser` 适用于手动打开页面，`--port` 修改网页端口。按 Ctrl+C 同时停止网页服务和仿真。

启动时先加载 Transformer，再初始化机械臂和相机首帧，避免连续渲染拖慢 PyTorch 导入。终端分别显示模型、仿真和后端准备总耗时。自动打开浏览器在后台进行，不阻塞网页请求；网页打开时仿真和模型都已就绪。浏览器未能自动打开时，终端会提示手动访问地址。

服务仅监听 `127.0.0.1`，用于本机作业演示。启动器会自动切换到项目已安装 PyTorch 的 `.venv_train` 环境，也可直接使用 `.venv_train/bin/python -B launch/web.py`。

## 点选、编辑与实际试抓

1. 等待右上角显示“后端已连接”，画面显示 Panda 和三色方块。新物体库为空，名称、别名和抓取坐标不预填。
2. 可点击画面任意位置，包括方块、地面和机械臂表面；也可使用颜色按钮定位方块。无有效深度的背景会按 Z=0 地面平面投影，并明确提示坐标来源。
3. 右侧显示 X/Y/Z 坐标，单位为米，采用 PyBullet 世界坐标。显示、保存和执行统一保留三位小数，例如 `0.550`。未登记目标的名称和别名留空，由你填写。
4. 按需编辑坐标，填写名称后点击“保存物体”才加入物体库。也可以先不命名、不保存，直接试抓当前坐标；点选与试抓均不会自动登记。
5. 点击“按坐标试抓”。机械臂按输入位置靠近、下降、闭合夹爪并抬升，网页显示实时运动与五阶段进度。
6. 查看成功/失败、坐标与方块中心的误差、夹爪到位误差、抬升高度及稳定夹持时间。
7. 点击“重置场景”，恢复机械臂和方块后重新点选测试。名称、别名和保存的坐标不会被重置覆盖。

每次测试都使用请求中的 `grasp_position`，不会用方块真值中心替换编辑后的坐标。真值仅参与结果验证和误差计算。故意把坐标移到方块旁边，测试会如实失败。

坐标来自当前显示帧的深度反投影。命中方块时，将表面位置沿命中面法线减去半边长 0.025 m 得到抓取参考点，保留切向误差。命中机械臂等其他表面时直接记录表面坐标；地面或背景使用视线与 Z=0 平面的交点。选点标记位于用户实际点击的位置。普通点位可自行命名、保存和再次编辑，无需绑定已有方块。

采集和保存坐标不限于抓取工作区；执行仍检查机械臂工作区和真实可达性。选择空处也可以在工作区内试抓，此时通过实际双指接触找到夹持物，再验证抬升；没有夹到方块时如实失败，不按距离猜测目标或吸附到方块。默认方块抓取仍建议点击其上表面中部。

成功判据沿用原项目：指定目标抬升至少 15 cm，并保持双指接触 3 秒。每次测试后保留物理状态，需要重置后再进行下一轮。

“停止任务”独立于语言模型，后端确认停止后保持当前位置。“重置场景”可中断当前抓取，然后恢复初始物理场景。

## 中文指令与自定义任务

### 点选登记放置点

1. 点击侧栏“放置点”→“登记放置点”，或将工作台右侧的“登记类型”切换为“放置点”。
2. 在相机画面点击空白地面或方块顶部中央，采集放置表面 XYZ；显示、保存和执行仍使用三位小数。地面通常为 `Z=0.000`，落地的 5 cm 方块顶部通常为 `Z=0.050`。
3. 填写名称（如“放置区A”）和可选别名，点击“保存放置点”。放置点独立保存，支持搜索、修改和删除。编辑已有点时重新点击画面可更新其位置；点击“新建”可继续登记其他点。
4. 在任务编排的“放下”步骤分别选择物体和放置点。后端自动移动并放置，可以只配置“抓取 → 放下”。

放置点坐标表示承托方块的表面，不是方块中心或夹爪高度。支持地面和水平方块顶部，包括已经堆叠的方块；支撑方块不必先登记进物体库。方块顶部选点应离边缘至少 5 mm。侧面、倾斜面、悬空位置、工作区外位置或已被上层方块占用的位置会被拒绝。支撑移走后应重新采集，程序不会吸附到其他位置。引用中的点不能直接删除，物体库和任务库原有数据保留。

例如：先登记红块为“零件A”，再切换“放置点”并点击蓝块顶部中央，保存为“蓝块顶部”。执行“抓取零件A”，成功后执行“把零件A放到蓝块顶部”；也可以保存一个“抓取 → 放下到蓝块顶部”的任务。后端在夹爪退出后继续验证 1 秒真实接触、支撑链、速度和位置误差，失败就如实停止。新增顶部放置点不改变模型权重和词表。

### 语言调用

登记目标后输入“帮我抓取你的目标名称”或使用其别名，点击解析并检查目标，再点击执行。页面展示提取后的有效命令、真实 Transformer 预测动作和数据库目标；请求详情保留原始输入和完整名称替换结果。模型只识别动作，不识别颜色或方向。

支持“我在上课，我想收拾零件”“想一想，我要收拾零件”“我在打游戏，我想抓取零件A”等请求，前提是名称已登记且只有一个命令。后端根据目标和现有动作词提取有效片段，让 Transformer 识别 `<TASK>` 或“抓取<OBJ>”；背景闲话不进入模型，也不需要逐词检查。没有标点时，现有动作词与目标之间的片段同样可以提取。不使用整句词语白名单，也不因未知字符比例拒绝输入。若希望“整理零件”也表示“收拾零件”，请在任务别名中登记。否定、条件、询问、预约时间、多目标及多动作等要求仍会检查；“抓取零件A，放下”需要保存为组合任务。模型仍可能因意图或置信度拒绝新表达。

在“任务编排”中保存任务名称、别名和 GRASP / MOVE / PLACE / WAIT 步骤，即可从列表运行，或输入“执行任务名称”。新增名称和任务不改变模型权重或词表。

MOVE 的 XYZ 表示夹爪参考点的绝对世界坐标；物体库中的普通命名点位也可通过“移动到点位名称”调用。独立的放置点提供支撑面位置。PLACE 必须带放置点，如“把零件A放到放置区A”或“放到放置区A”；操作当前已夹持物体，不会隐式抓取其他目标。

执行器按保存坐标和当前夹持偏移换算末端目标，移动、下降、释放，再检查真实支撑和稳定状态。放置误差及实际位置包含在执行结果中。任务中途失败就停止后续步骤。

连续任务与坐标试抓分开：正常任务完成后不要求每步重置，抓取后可继续说“放到放置区A”；失败或停止后需要重置。没有指定放置点的“放下当前物体”会要求补充目的地。物体移动后，数据库中旧示教坐标保留，后续抓取前应重新采集。

未知目标、多目标、否定表达和无效参数不会生成可执行结果。语言解析凭据有效期 120 秒且只能执行一次；登记内容、场景或执行状态变化后需重新解析。独立停止按钮不依赖模型。

## 已实现功能

- 已实现：实时 PyBullet 相机、同帧深度点选、坐标编辑、真实抓取验证、进度和结果、停止与重置。
- 已实现：物体名称、别名、坐标和技能 ID 的 SQLite 存储，以及任务配置的保存和编辑。
- 已实现：四层 Transformer 七分类推理、动态名称匹配、一次性解析凭据、GRASP / MOVE / PLACE / WAIT 连续任务执行。
- 旧小模型已替换；训练脚本、数据、权重和真实实验结果见 [../llm/README.md](../llm/README.md)。Qwen 文件保留，但前端不再提供切换入口。
- 原有两参数 `grasp_cube()` 调用继续可用。

数据库默认位于 `backend/data/registry.sqlite3`，首次启动物体、放置点和任务库均为空；之后只读取用户保存的内容。新增放置点表不会清空旧数据。删除所有登记后重新启动仍为空，重置物理场景也不会自动导入目标。可用 `--database /path/to/registry.sqlite3` 指定位置。SQLite 物体 ID 与 PyBullet 临时 body ID 分开。

侧栏底部的“清除所有记忆”会先显示删除范围，确认后停止当前任务、重置场景，并清空当前后端数据库中的物体、名称别名、坐标、放置点和任务，同时清除解析凭据、运行记录及页面草稿。清除后重新启动仍为空，可以重新登记。训练数据、模型权重和接口设置保留。此操作会永久删除上述登记；仅点击“重置场景”仍会保留登记。

本地预览模式下，同一按钮只清空当前浏览器的预览物体、放置点和任务，不会访问后端数据库。

旧版本的 `backend/data/studio.sqlite3` 中可能包含自动登记和用户编辑的数据，本次保留原文件，未清空或覆盖。如需查看旧登记，可显式使用 `--database backend/data/studio.sqlite3`。静态预览也使用新的空库键 `panda.frontend.preview.v2`，旧浏览器数据仍保留在 v1 键中。

## 接口与代码

- `index.html`、`styles.css`、`app.js`：前端页面、样式、交互与状态。
- `api.js`：HTTP 后端适配器，以及保留的静态预览适配器。
- `config.js`：连接配置。一体化服务的 `/studio-config.json` 覆盖旧浏览器预览设置，并自动适配启动端口。
- `coordinates.js`：三位小数记录、输入格式化与投影换算。
- `frame_stream.js`：连续相机流解码，保持图像与点选帧配对。
- `../backend/simulation.py`：单线程物理仿真、相机帧、深度拾取与异步抓取。
- `../backend/store.py`：SQLite 物体与任务配置。
- `../backend/server.py`：本地网页及 JSON / PNG 接口。
- `../launch/web.py`：统一启动入口。
- [API.md](API.md)：后端协议与当前实现范围。

单独运行静态文件服务时，需在“接口设置”中明确选择“本地预览”才显示历史截图和规则预览；该模式不会驱动机械臂，也不用于坐标准确度验证。`assets/` 和 `tools/render_scene.py` 只服务于静态预览。正常试抓使用统一启动命令。

## 检查

相机通过一个持续 HTTP 连接推送 PNG 与同帧元数据，前端在固定 canvas 中绘制，不逐帧发起图像请求或替换 DOM。默认画面为 640×400，关闭软件阴影，目标上限 24 FPS；画面右下角显示实际接收 FPS。实际帧率取决于软件渲染速度，不能保证所有设备达到 24 FPS。`--gui` 模式使用 PyBullet 原生 OpenGL 相机。

在项目根目录运行：

```bash
node --test frontend/tests/*.test.js
.venv_train/bin/python -B -m unittest discover -s tests -v
```

物理检查包括三色方块点选后成功抓取、偏移 10 cm 后失败、编辑坐标优先于数据库坐标、停止与重置、SQLite 持久化，以及 HTTP JSON / PNG 响应。HTTP Handler 使用内存收发验证协议，不依赖测试环境的监听端口权限。
